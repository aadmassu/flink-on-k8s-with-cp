The current Kafka CR uses externalAccess.type: loadBalancer, which would create per-broker LoadBalancer Services for external Kafka listeners (9092 SASL_SSL / 9094 mTLS). Is this acceptable, or should we use an external HAProxy/F5 solution on the native Kafka ports instead? The same question applies to the HTTP-based services (Schema Registry, Connect, REST Proxy, MDS, Control Center, CMF, and Flink JobManager). The current design terminates on HAProxy at port 443, which would require producers, consumers, and administrative clients to change URLs and ports during the VM CP → CFK migration.
