INTERPRETATION — three theories, one query each
------------------------------------------------------------------------------

Q1 tells us what URL/response the operator got when trying to create rolebindings.
Look for:
  - HTTP status codes in the log message body (0 = no response, 401 = auth failed,
    404 = wrong path, 5xx = broker-side issue)
  - TLS errors mentioning "unable to find valid certification path" or
    "SSLHandshakeException" — would indicate operator's truststore doesn't
    trust broker's kafka-tls (though Rick installed operator with fcb-trust-bundle,
    so this should not fire; if it does, we need Rick to verify)
  - "failed to acquire access token from IdP" or similar — operator's own
    Okta client_credentials (oauth-broker or oauth-mds-rest Secret) are rejected

Q2 zooms in on our 5 explicit rolebindings + the 3 CFK-auto-generated ones.
The operator should log one line per rolebinding it tries to create, with the
request URL. Confirms the exact endpoint the "Not Found (0)" is coming from.

Q3 is THE smoking gun for the most likely root cause. If we see
UnknownHostException/SocketTimeoutException/ConnectException with
myapps.firstcitizens.com in the message text, the broker pods cannot reach
Okta from inside dah-flink-dev. The token-verification loop then times out
(broker doesn't respond to the client's SASL OAUTHBEARER handshake in time),
explaining BOTH (A) — operator's token can't be validated by MDS — AND (B) —
SR's token can't be validated by broker at :9073.
