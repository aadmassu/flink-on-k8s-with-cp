PHASE 2 PLAN — gated on Phase 1 stability
=========================================

Once Phase 1 has held cluster-ready=True for at least 1 hour
without flipping, layer Phase 2 in this order:

1. Add `spec.authorization` block to kafka.yaml:
     authorization:
       type: rbac     # confirm enum via oc explain
       superUsers:
         - User:admin
   Replace the configOverrides.server `super.users` line.

2. Add `spec.services.mds` to kafka.yaml with the full Okta-
   backed OAuth provider config. Wire from sasl-plain-internal +
   mds-token-keypair + oauth-mds-rest secrets. Verify post-
   admission that the block survives.

3. Add `ConfluentServerAuthorizer` + `providers=CONFLUENT,KRAFT_ACL`
   back to broker configOverrides.server. Now MDS exists so the
   RBAC provider initializes cleanly.

4. Swap kafka.yaml `external` listener auth from `plain` to
   `oauth` + `oauthSettings` (Okta values from variable group).

5. Add `listeners.custom[name=certonly]` mTLS listener once a
   client-CA Secret is provisioned by Container/Security teams.

6. SR — add `spec.authentication` (OAuth), `spec.authorization`
   (rbac), `dependencies.mds`. Re-add JETTY_AUTH + SR security
   extension in configOverrides.

7. Connect / REST Proxy / Control Center — bring online once
   Phase 2 SR is green. Apply existing yamls (already have full
   OAuth+MDS+RBAC); their dependencies.kafka should be updated to
   use the new SASL/PLAIN-or-OAUTHBEARER target.

8. Re-add the three telemetry-reporter lines once FCB provisions
   the telemetry API creds (memory
   project_fcb_telemetry_audit_reenable_later).
