## Purpose

Proposed Azure DevOps Environments backing the multi-stage YAML CD
pipelines for Flink/CFK delivery on OpenShift. Three workload classes
× five envs:

  flink-jobs-<env>  — application code (DAH.Flink.Jobs ci.yaml + cd.yaml)
  cp-<env>          — Confluent Platform CFK CRs (DAH.Kafka.OS confluent-platform.yaml)
  cmf-<env>         — CMF + Flink Operator (DAH.Kafka.OS cmf.yaml)

  <env> ∈ { dev, qa, uat, prd, dr }

The existing DBA-owned Environments (Dev / QA / Uat / prod, used by
DAH.DB sql and SSIS.SqlScripts) stay untouched — different approvers,
different change-management policy, different cadence.


## Conventions

- Names are lowercase kebab-case (flink-jobs-dev, not Flink-Jobs-Dev).
  Keeps YAML `environment:` references consistent and avoids the casing
  drift the DBA envs already exhibit (Dev / QA / Uat / prod — three
  conventions in four envs).
- Branch control check on every non-dev Environment restricts the
  triggering branch to `master`. Dev allows feature branches so engineers
  can iterate.
- Exclusive lock check enabled on every Environment so concurrent
  pipeline runs serialize per env — prevents two engineers stepping on
  each other's CFK CR applies or CMF Helm bumps.
- ServiceNow gate applied at *-prd and *-dr only. Uses the "Invoke REST
  API" check pointing at the CITMain SNOW change-window endpoint
  (exact URL TBC with FCB Change Management).
- Business-hours gate (09:00–17:00 ET, Mon–Fri) on *-prd. Intentionally
  NOT on *-dr — DR deploys are incident-driven, must work any time.

## Definitions


### 1. flink-jobs-dev
Pipeline:        DAH.Flink.Jobs / cd.yaml (Dev stage)
Deploys:         FlinkApplication CR + ConfigMap per Flink job
Branch control:  any branch (engineers iterate on feature branches)
Approvers:       none (auto-deploy)
Pre-deploy:      Exclusive lock
Post-deploy:     none

### 2. flink-jobs-qa
Pipeline:        DAH.Flink.Jobs / cd.yaml (QA stage)
Deploys:         FlinkApplication CR + ConfigMap per Flink job
Branch control:  master only
Approvers:       KAFKA-ADMINS (any 1 of 3)
Pre-deploy:      Exclusive lock, branch=master
Timeout:         24 hours; reject on timeout

### 3. flink-jobs-uat
Pipeline:        DAH.Flink.Jobs / cd.yaml (UAT stage)
Deploys:         FlinkApplication CR + ConfigMap per Flink job
Branch control:  master only
Approvers:       KAFKA-ADMINS (any 1 of 3)
Pre-deploy:      Exclusive lock, branch=master
Timeout:         24 hours; reject on timeout

### 4. flink-jobs-prd
Pipeline:        DAH.Flink.Jobs / cd.yaml (Prd stage)
Deploys:         FlinkApplication CR + ConfigMap per Flink job
                 (image promoted from dev registry to prod registry first)
Branch control:  master only
Approvers:       KAFKA-ADMINS (Tushar required) + CHANGE-MGMT
Pre-deploy:      Exclusive lock, branch=master, ServiceNow change-window
                 gate, business-hours gate (09:00–17:00 ET, Mon–Fri)
Timeout:         48 hours; reject on timeout

### 5. flink-jobs-dr
Pipeline:        DAH.Flink.Jobs / cd.yaml (Dr stage; not yet active)
Deploys:         FlinkApplication CR + ConfigMap per Flink job on the
                 secondary cluster. Normally idle; deploys only on
                 failover or when state diverges from prd.
Branch control:  master only
Approvers:       KAFKA-ADMINS (Tushar required) + CONTAINER + CHANGE-MGMT
                 (DR deploys are inherently incidents — extra reviewer)
Pre-deploy:      Exclusive lock, branch=master, ServiceNow change-window gate
Timeout:         48 hours; reject on timeout


### 6. cp-dev
Pipeline:        DAH.Kafka.OS / confluent-platform.yaml (environment=dev)
Deploys:         CFK CRs (KRaftController, Kafka, SchemaRegistry, Connect,
                 KafkaRestProxy, ControlCenter), prereq Secrets,
                 cert-manager Certificate CRs, Ingress
Branch control:  any branch (dev is the experimentation env)
Approvers:       none (auto-deploy)
Pre-deploy:      Exclusive lock

### 7. cp-qa

Deploys:         CFK CRs + prereqs + certs + Ingress
Branch control:  fcb-flink-cp only
Approvers:       KAFKA-ADMINS (Tushar required) + CONTAINER (Rick OR Tom)
Pre-deploy:      Exclusive lock
Timeout:         48 hours; reject on timeout

### 8. cp-uat
