    Read this before the wire diagram: Route 53 only ever answers a DNS question — it never carries application traffic. The NLB only receives traffic after the client has already resolved a name to an IP. The NLB forwards to OpenShift Router pods running on worker nodes; the worker node itself is never directly exposed to DNS resolution. The Service and EndpointSlice live one layer up, on the pod overlay network — not on any VPC CIDR.

    02 · DNS resolution sequence

    Wildcard CNAME → NLB DNS name

    Hosted zone dev.confluent.psyncopate.io. Wildcard record *.dev.confluent.psyncopate.io → CNAME → internal-cfk-dev-nlb-abc123.elb.amazonaws.com.

    Client
    DNS Resolver
    Route 53
    NLB (AWS-managed A records)
    query: schemaregistry.dev.confluent.psyncopate.io A?
    recurse to Route53 authoritative NS
    CNAME → internal-cfk-dev-nlb-abc123.elb.amazonaws.com
    resolve NLB DNS name (AWS-managed zone)
    A records: 10.0.1.25, 10.0.2.25, 10.0.3.25
    final answer returned to client
    Route 53 resolves the name. It has no idea whether port 443 is reachable, whether the firewall will allow the connection, or whether any pod is healthy — those are separate systems, and separate failure domains.

    03 · Firewall policy engine

    AWS Network Firewall — stateful inspection layer

    Sits in the private route table's default path (0.0.0.0/0 → firewall endpoint) for egress, and inline before the router for ingress. It inspects and filters; it is not DNS and it is not the load balancer.

    Ingress

    Allow inbound TCP 443 only from approved corporate CIDRs.

    Egress

    Allow outbound HTTPS only to an explicit FQDN allow-list.

    DNS

    Allow DNS egress (TCP/UDP 53) only to approved resolvers.

    Default

    Deny all other inbound and outbound traffic by default.

    04 · OpenShift routing chain

    Router → Route → Service → EndpointSlice → Pod

    Once the firewall allows the TCP 443 connection, HAProxy on the worker node takes over entirely.

    1

    Router (HAProxy)

    router-default pods listen on 443 across worker nodes. Reads SNI for passthrough routes, or Host header after TLS termination for edge/reencrypt routes.

    2

    Route match

    Host schemaregistry.dev.confluent.psyncopate.io is matched against the schemaregistry Route object in namespace confluent.

    3

    Service selection

    Route points to Service schema-registry-svc (ClusterIP 172.30.10.40:8081) — a stable virtual IP, never the pod IP directly.

    4

    EndpointSlice → Pod

    kube-proxy resolves the Service to the EndpointSlice's healthy pod IPs — 10.128.2.45:8081 and 10.129.4.18:8081 — and forwards.

    05 · Service & EndpointSlice

    Why the Service IP is never the destination

    Service = stable identity

    ClusterIP 172.30.10.40 never changes even as pods are rescheduled, scaled, or replaced. Clients (and the router) only ever need to know this one address.

    EndpointSlice = live membership

    Continuously reconciled list of ready pod IP:port pairs backing the Service. A pod failing readiness probes is removed here first — before it ever affects the Route.

    Pod = the actual workload

    schema-registry-0 on worker-b and schema-registry-1 on worker-c are the only two IPs that ever terminate the TCP connection and answer on 8081.

    If the EndpointSlice has zero ready addresses, the Service has nothing to forward to — that's precisely the 503 failure mode in the matrix below, and it has nothing to do with DNS, the firewall, or the NLB.

    06 · What breaks where?

    Failure troubleshooting matrix

    Pick a symptom from the dropdown in the top bar (or click a card) to highlight the exact layer on the diagram above.

    DNS layer

    NXDOMAIN

    Route53 hosted zone or wildcard record missing/misconfigured.

    Network path

    Timeout to hostname

    Firewall, NLB, route table, security group, or NACL is dropping the connection silently.

    Router / TLS

    TLS error

    Certificate mismatch or wrong Route termination type (edge/passthrough/reencrypt).

    OpenShift Route

    404 Not Found

    Host header doesn't match any Route — router mismatch, not a Service problem.

    Service

    503 Service Unavailable

    Service resolved fine, but its EndpointSlice has no ready pod addresses.

    Pod / container

    Connection refused

    Pod is up but nothing is listening on the expected container port.

    Egress

    ImagePullBackOff

    Worker node can't reach quay.io / registry.redhat.io — check NAT, firewall allow-list, and DNS egress.

    Egress / IdP

    OAuth JWKS timeout

    Pod can't reach Okta's well-known endpoint — firewall allow-list or NAT Gateway issue.
