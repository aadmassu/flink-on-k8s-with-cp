## Accomplishments

- **`aep-rate-limit-job` Flink job successfully deployed in `dah-flink-dev`**. This is the first end-to-end Flink-on-CFK job running in the new dev stack. Required diagnosing and working around three distinct Apache Flink Operator behaviors at FCB:
  - Deployment-level label propagation gap — the operator carries `fcbint.net/*` labels to the Deployment but filters `app.kubernetes.io/*`; FCB Gatekeeper `[required-workload-labels]` denied the POST. Worked around by adding the full FCB common-metadata set to the FlinkDeployment CR's top-level `metadata.labels` (which the operator copies to the Deployment), rather than relying solely on the pod-template labels. Runbook G1 hypothesis is now confirmed by debug-log evidence.
  - Missing `livenessProbe` / `readinessProbe` on the operator-generated pod — Flink Operator only emits a `startupProbe` (with `failureThreshold: 2147483647`, effectively disabled, by design). FCB Gatekeeper `[readiness-liveness]` denied. Worked around by adding explicit probes via `spec.podTemplate.spec.containers[].livenessProbe` / `readinessProbe` pointing at `/config` on the `rest` port. Same shape as the CFK `[startup]` constraint gap.
  - Compute footprint — the dev environment defaults (1 CPU / 4000m JM + 1 CPU / 4000m TM, 2 task slots) would have demanded 2 CPU / 8 GiB just for one Flink job, leaving no room for CFK pods. Reduced to 0.5 CPU / 1024m per JM/TM with 1 slot for `dah-flink-dev` only.
- **DEV ResourceQuota CPU + memory portion raised** by Container team — sufficient headroom for the full CFK stack plus Flink jobs. Connect + ControlCenter can be brought back from `replicas: 0` when re-prioritized. Storage piece moved from 10 GB to 100 GB in the same pass (workable for current dev smoke testing but still ~12× short of the ~1.272 TB per-env workbook target). Tracker 2.5 status downgraded from OPEN / BLOCKER → OPEN.
- **Shrunk `apps/confluent-flink/dev/environment.json` FlinkApplication + compute-pool defaults** — JM/TM CPU `1 → 0.5`, memory `4000m → 1024m`, `taskmanager.numberOfTaskSlots: "2" → "1"`. Any future Flink job in dev that doesn't override now defaults to ~1 CPU / 2 GiB total. QA / UAT / PRD intentionally left at the older defaults — those should be sized per the Application Infrastructure Workbook before per-env promotion.
- **Diagnosed two distinct admission denials** from the same Flink job via the DEBUG logs enabled in last week's RITM1080156 (tracker 3.1 close) — without DEBUG, both failures would have surfaced as opaque "Deployment rejected" events. Validated that the DEBUG investment was load-bearing for this week's progress.
- **Confirmed FCB's Flink Operator install runs with `defaultConfiguration.append: false`** and DEBUG logging still flows correctly (counter to the upstream chart's documented `append: true` requirement). Saved as a project memory so the upstream chart behavior isn't relitigated.
- **Recovered 4 prereq Secrets stuck in Terminating with CFK finalizers** (`cfk-license`, `connect-tls`, `mds-token-keypair`, `oauth-connect`). Introduced a pipeline-driven, ESO-safe finalizer cleanup action (`clear-stuck-prereq-finalizers`) — selectively removes only `secret.finalizers.platform.confluent.io/*` entries so ESO's own bookkeeping (`external-secrets.io/finalizer` on `confluent-license`, `cmf-encryption-key`, `cmf-db-credentials`) is preserved. Pipeline-driven because the kafka team has no shell access. Runbook A13 + H4 capture the gotcha and the Python-heredoc-in-YAML pitfall the fix uncovered.
- **Extended ESO + CyberArk integration for the Confluent license across all SDLC envs** (dev / qa / uat / prd / dr). Adds `confluent-license` ExternalSecrets under `apps/confluent-cmf/<env>/externalsecrets/` for the four envs that previously fell back to the variable group, and adds `cfk-license` ExternalSecrets under `apps/confluent-platform/<env>/externalsecrets/` for every env (same source JWT, wrapped as `license=<JWT>` via the ESO template — CFK operator wants the Java-properties shape, CMF wants the raw JWT). One CyberArk account per env, two output Secrets. Pipeline wiring to apply these (cmf.yaml + confluent-platform.yaml) is the next remaining step.
- **Hardened `create-prereqs` to skip Secrets that are ESO-managed** — snapshots every `ExternalSecret.spec.target.name` per namespace at the top of the action, then short-circuits the three helper functions (`apply_secret_from_literals`, `apply_secret_from_file`, `apply_oauth_secret`) plus the two inline blocks (`mds-token-keypair`, `sasl-plain-internal`). Reads ESO ownership from the live cluster so future ExternalSecrets are picked up automatically with no code change.
- **Fixed Schema Registry CrashLoopBackOff race vs Kafka boot** — install action now phases the apply: kraftcontroller + kafka → poll `platform.confluent.io/cluster-ready=True` (15-min ceiling per CR, 60s heartbeat with live condition table) → schemaregistry + connect + kafkarest + controlcenter. SR pod can no longer hit `kafkastore.init.timeout.ms` against an unready broker. Runbook A14 captures the root cause and explains why a pod-level `initContainer` isn't an option (CFK 3.1.x CRDs don't expose one — cross-refs A3).
- **Two new pipeline actions + one rename**: `diagnostics` runs the existing install pre-step dump standalone (read-only triage without touching cluster state); `clear-stuck-prereq-finalizers` recovers from the stuck-Secret pattern above; `install` renamed to `install-or-update` since `oc apply` is idempotent and does both. `install-or-update` exposes per-component checkboxes ("All" default-checked master + 6 individual components defaulting unchecked) — supports the Confluent-recommended cluster upgrade pattern (kraft → kafka → SR/Connect/REST → C3) as one pipeline run per stage instead of a big-bang re-apply.
- **Renamed `apps/confluent-platform/<env>/prereqs/` → `cert-manager/`** across dev / qa / uat. The folder only ever held cert-manager Certificate CRs that issue `*-tls` Secrets via Keyfactor — `prereqs` was a misnomer because the non-TLS prereqs (license, MDS keypair, OAuth, SASL) are pipeline-created, not manifest-based. 18 files moved as git renames (history preserved). Pipeline updated at the three reference sites (REQUIRED_FILES check, install apply loop, uninstall delete loop).
